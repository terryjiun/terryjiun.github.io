tags: [Windows, 工作管理員]

以前筆者想要知道 Windows 2000/XP/2003 已經開機多久（沒再重新開機過），<br>
最常用的方式是直接開啟網路連線的狀態，查看「連線時間」。<br>
因為筆者通常開機後，就不會將網路連線停用再啟用，<br>
所以這不失為一個獲知「此次開機後，系統已經運作多久」的好方法。<br>
筆者管理的電腦及伺服器裡，曾經有一台 Windows 2000 Server 在支援服務到期後，<br>
因為沒有 Windows Update 的 hotfix 檔可供使用，所以有過三個月至四個月沒重新開機過的經驗。<br>
那台伺服器負責擔任 FTP 的任務，同仁（超過百位）使用掃描器時，掃描後的檔案都會儲存在這部伺服器，<br>
所以每天的使用率算是相當高的，但是這麼長的時間，沒重新開機過，所有程式都運作正常，這很值得慶幸。<br>
<br>
上個月的某個週末，筆者打開家中桌機的 Windows 10 「工作管理員」，查看「效能」頁籤時，<br>
突然發現「運作時間」這一欄居然出現 12 天這樣的驚人數字！<br>
筆者是個響應節能減碳的人士，家裡的電腦開機時，一定讓它有事情做，<br>
就算是在寫文章，也會讓它同時播放音樂，又同時下載影片或軟體，<br>
而且睡覺前一定會關機，所以很納悶怎麼會出現 12 天這樣的數值，<br>
於是開啟了網路連線狀態的視窗查看了一下，沒想到它的「連線時間」也是顯示 12 天這樣的結果。<br>
另外，執行「<span style="color: purple">systeminfo</span>」指令所得到的「<span style="color: purple">系統開機時間</span>」也是 12 天前。<br>
唯一例外的情況是：<br>
如果此次開機，系統有執行過 Windows Update，關機時選擇「更新並關機」，<br>
那麼下次再開啟電源，讓 Windows 執行完更新後，這時「系統開機時間」就會重新計算了！<br>
<br>
<span style="color: red">筆者心想：這大概是 Windows 8/8.1/10 關機設定的「快速啟動」這個功能在作祟！</span><br>
因為筆者這 12 天，並非每天至少開機一次，有時隔了兩三天才又開機一次，<br>
但是一旦開機後，用完都是直接關機，未曾使用過系統的「重新啟動」這個選項。<br>
<span style="color: blue">於是當下就執行了一次「開始→開啟/關閉→重新啟動」，果然重新開機後，<br>
上述工作管理員的「運作時間」、網路狀態的「連線時間」、SystemInfo 的「系統開機時間」就重新計算了！</span><br>
<br>
Windows 8/8.1/10 的「快速啟動」設定路徑為：<br>
「控制台→(系統及安全性)→電源選項」，在「喚醒時需要密碼」頁面下方可以看到：<br>
「開啟快速啟動 (建議選項)」這行文字，如果顯示灰色，不能勾選（或取消勾選）的話，<br>
點選上方【變更目前無法使用的設定】選項（前提是必須以系統管理者帳戶登入 Windows），<br>
然後就可以取消勾選（或勾選了）！<br>
勾選時，代表啟用「快速啟動」這項功能，<br>
雖然會出現上述「運作時間」、「連線時間」、「系統開機時間」失準的情形，<br>
但是會讓下次開機（此處指關閉電源後再開機）的載入時間縮短而變快，<br>
因此如何取捨就看個人了！<br>
<br>
如果不停用「快速啟動」的話，應該還是有其他方式可以查看正確的系統開機時間，<br>
像是由「事件檢視器」的事件時間也可以推知，<br>
不過，筆者還是期盼未來 Microsoft 可以改進這個情形。
